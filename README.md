# Link-Me (`MacBridge` + `AndroidBridge`)

Local-first, zero-cloud continuity bridge between **macOS 14+** (Swift 6 / SwiftUI `MenuBarExtra`) and **Android 10+** (Kotlin / Jetpack Compose / `connectedDevice` ForegroundService).

---

## Architecture Overview

Link-Me combines a low-power Bluetooth Low Energy (BLE) control/beacon plane with an on-demand Wi-Fi mutual TLS 1.3 data plane, governed by a deterministic 4-state battery state machine:

```
DORMANT_BLE ──(BLE wake / local event)──▶ HANDSHAKE_WAKE ──(mDNS + mTLS 1.3 OK)──▶ ACTIVE_WIFI_STREAM
     ▲                                                                                      │
     │                                                                            (45s idle, no file stream)
     └────────────────────(15s grace timer expires -> close Wi-Fi socket)──────── COOLDOWN_IDLE ◀─────────┘
```

- **`DORMANT_BLE` (Default Idle):** All Wi-Fi TCP/TLS sockets are closed. Android advertises a rotating 8-byte `BlePrivacyBeacon` at `ADVERTISE_MODE_LOW_POWER` (suspended automatically when Battery Saver is active), while macOS scans passively filtered strictly by GATT Service UUID `414D0001-0000-1000-8000-00805F9B34FB` (ASCII `"AM01"` hex).
- **Low-Latency BLE Control (`<= 400 B`):** Telemetry pings, short clipboard updates, and remote commands travel directly over BLE GATT (`ControlWriteChar` / `ControlNotifyChar`, chunked at `MTU - 3`) without waking Wi-Fi.
- **On-Demand Wi-Fi Turbo (`> 400 B` / High-Throughput):** `WAKE_WIFI` over BLE triggers Bonjour/mDNS (`_andromac._tcp`) discovery and a pinned TLS 1.3 mTLS socket (`Network.framework` on macOS, `SSLServerSocket`/`SSLSocket` on Android) with a resettable 15-second `COOLDOWN_IDLE` teardown timer.

## Security Guarantees

1. **Out-of-Band Curve25519 QR Pairing + 6-Digit SAS:** Ephemeral X25519 keypairs (5-minute TTL) + `HKDF-SHA256("AndroMac-Pairing-v1")` derive both a 6-digit Short Authentication String (SAS) for human MITM verification and a 32-byte `sharedBleSecret`.
2. **Hardware-Backed Identity & mTLS 1.3 Certificate Pinning:** Both devices generate local P-256 keypairs and 10-year self-signed X.509 certificates stored in **macOS Keychain** (`kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`) and **Android Keystore**. Peer fingerprints are stored in `TrustStore` (AES-256-GCM Keystore-encrypted on Android) and verified in constant time; public CA trust stores are bypassed.
3. **15-Minute Rotating BLE Privacy Beacons:** `HMAC-SHA256(sharedBleSecret, uint64_be(floor(unix_ts / 900)))[0..<8]` prevents passive BLE tracking while allowing `±1` bucket (`±15 min`) clock-skew verification.
4. **Framed Binary Protocol & Anti-Replay:** Every frame enforces `Magic == 0x414D`, `Version == 0x01`, `MsgType in 0x01...0x09`, `PayloadLength <= 1 MB`, and a 64-bit sliding `ReplayGuard` window.
5. **Path-Traversal & Clipboard Secret Guardrails:** `FilenameSanitizer` strips `../`, `/`, `\`, drive prefixes, NUL/control characters, and leading dots (200-byte UTF-8 cap preserving extensions) before any write; transfers stream in `64 KB` chunks into `.part` staging files verified by incremental SHA-256. Concealed clipboard entries (`org.nspasteboard.ConcealedType` / `TransientType` / `AutoGeneratedType` and Android `ClipDescription.EXTRA_IS_SENSITIVE`) are dropped pre-sync, and remote writes update `lastSyncedContentHash` before mutating the clipboard to prevent echo loops.

## Build from Source

### macOS (`MacBridge`, macOS 14+ / Swift 6)

```bash
cd macos
swift test
swift build -c release
```

> **Note on Command Line Tools:** If building with standalone Apple Command Line Tools (without full Xcode), run:
> ```bash
> swift test -Xswiftc -plugin-path -Xswiftc /Library/Developer/CommandLineTools/usr/lib/swift/host/plugins/testing
> ```

### Android (`AndroidBridge`, JDK 17 / Android SDK 35)

```bash
cd android
./gradlew testDebugUnitTest assembleDebug
```

## Installing Release Binaries (`MacBridge.dmg` & `AndroidBridge.apk`)

Tagged releases (`v*`) attach `MacBridge-v*.dmg`, `AndroidBridge-v*.apk`, and `SHA256SUMS.txt`.

### Opening an Ad-Hoc Signed `.dmg` on macOS
Release `.dmg` builds produced in CI are **ad-hoc signed** (`codesign --sign -`) rather than Apple Developer ID notarized, so macOS Gatekeeper will warn on first launch:

1. Open `MacBridge-<version>.dmg` and drag **MacBridge.app** into **Applications**.
2. Clear the download quarantine flag (recommended) or approve in **System Settings → Privacy & Security**:
   ```bash
   xattr -cr /Applications/MacBridge.app
   open /Applications/MacBridge.app
   ```
3. Grant **Bluetooth**, **Local Network**, and **Notifications** permissions when prompted. `MacBridge` runs as a menu-bar agent (`LSUIElement = true`) with no Dock icon.
